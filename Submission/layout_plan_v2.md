# Layout Plan V2

This plan is the visual contract for the rebuilt poster and deck. The goal is to make the submission look like a real game pitch, not a repeated document template.

## Poster Layout

### Purpose

Show the project as a cute workshop side-scrolling narrative action game at first glance.

### Structure

- Canvas: 1920 x 1080, 16:9.
- Safe margin: 72 px minimum.
- Left top title block: project title, English subtitle, track, one-sentence pitch.
- Center stage: large player sprite standing on tile ground.
- Right and rear stage: at least three enemy sprites forming a readable combat relationship.
- Left lower panel: "Workshop Memory Log" UI mock, showing that AI narrative appears inside the game experience.
- Bottom strip: three small screenshot slots. If no real screenshots exist, they must say "Waiting for Unity screenshot".
- Bottom right: Team and Demo Link placeholders.

### Visual Priority

1. Main character and enemy confrontation.
2. Memory log narrative panel.
3. Title and pitch.
4. Screenshot placeholders.
5. Team and Demo placeholders.

### Overlap Avoidance

- Title block cannot exceed 42% of poster width.
- Main character must not overlap title text.
- Screenshot placeholders stay in the bottom strip, never in the center.
- Memory log panel text uses high contrast and short lines.

## PPT Layout Plan

### Slide 1. Cover

- Purpose: make the deck feel like a game pitch immediately.
- Layout type: hero key visual.
- Visuals: `hero_stage.png`, player, enemies, tile ground.
- Text area: top-left title group only.
- Image area: center/right large stage composition.
- Avoid overlap: no bullet cards on this slide.

### Slide 2. What Is The Game

- Purpose: explain the game in one sentence and three keywords.
- Layout type: left image, right explanation.
- Visuals: `player_lineup.png` cropped/contained on the left.
- Text area: right column with one short paragraph and three keyword chips.
- Avoid overlap: text column width fixed; image contained inside a framed region.

### Slide 3. Core Gameplay Loop

- Purpose: show the full loop without bullet-page fatigue.
- Layout type: horizontal route / flow map.
- Visuals: `gameplay_loop_route.png`.
- Text area: small caption below the flow only.
- Avoid overlap: route nodes are evenly spaced with arrows.

### Slide 4. Cast And Enemies

- Purpose: show character and enemy variety.
- Layout type: card wall / lineup.
- Visuals: `player_lineup.png`, `enemy_lineup.png`, `npc_lineup.png`.
- Text area: three short labels.
- Avoid overlap: images stacked in separate bands.

### Slide 5. AI Narrative In Game

- Purpose: prove AI content enters UI and gameplay.
- Layout type: large memory-log UI mock.
- Visuals: `memory_log_mock.png`, NPC accent.
- Text area: right-side checklist of AI-generated content.
- Avoid overlap: log window uses large text; checklist is separate.

### Slide 6. Demo Flow

- Purpose: give teammate a 3-5 minute recording route.
- Layout type: timeline.
- Visuals: `demo_timeline.png`.
- Text area: timeline node labels only.
- Avoid overlap: screenshot slots are in one row and clearly marked if placeholder.

### Slide 7. Tech And Deployment

- Purpose: show implementation structure quickly.
- Layout type: module architecture diagram.
- Visuals: `tech_architecture.png`.
- Text area: small deployment note strip.
- Avoid overlap: node graph centered with enough spacing.

### Slide 8. Highlights And Submission Status

- Purpose: close with what is ready and what must be manually filled.
- Layout type: two-column board.
- Visuals: `submission_status_board.png`.
- Text area: left highlight column, right checklist column.
- Avoid overlap: no paragraph longer than two lines.

## Diversity Check

- Slide 1: hero key visual.
- Slide 2: left image / right text.
- Slide 3: route diagram.
- Slide 4: visual lineup.
- Slide 5: UI mock.
- Slide 6: timeline.
- Slide 7: architecture diagram.
- Slide 8: status board.

No two adjacent slides use the same layout.

## Shared Visual Rules

- Titles: at least 44 pt in PPT.
- Body text: at least 24 pt in PPT where possible.
- Poster text: no tiny labels except footer placeholders.
- Image scaling: contain or manual proportional scaling only.
- No external copyrighted assets.
- No fake deployment, video, screenshot, or CodeBuddy history.
